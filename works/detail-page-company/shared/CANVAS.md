# 상세페이지 포맷 계약 (전 단계 공통 · 최우선)

> 이 문서는 **우리가 만드는 물건이 무엇인지**를 정의한다.
> `COMPLIANCE.md`가 "무엇을 말해도 되는가"라면, 이 문서는 "무엇을 만드는가"다.
> 여기 어긋나면 카피가 아무리 좋아도 결과물은 쓸 수 없다.

---

## 0. 우리가 만드는 것

**상세페이지 = 쇼핑몰 상품 상세 영역에 올라가는 세로로 아주 긴 한 장(들)의 이미지다.**

최종 산출물은 `.jpg` 파일 묶음이다. HTML이 아니다.

HTML을 쓰는 이유는 단 하나 — **이미지로 내보내기 위한 조판(組版) 수단**이기 때문이다.
브라우저에서 사람이 열어 읽는 웹페이지가 아니다. 클릭할 사람이 없고, 검색엔진이 읽지 않고,
화면 크기에 맞춰 다시 흐를 일이 없다.

```
HTML(조판)  →  Chromium 렌더  →  세로 긴 캡처  →  슬라이스 .jpg  →  쇼핑몰 업로드
   ↑                                                    ↑
 우리가 쓰는 것                                      고객이 보는 것
```

### 단 하나의 판정 기준

> **"이 HTML을 스크린샷 한 장으로 찍었을 때, 만든 그대로 100% 나오는가?"**

아니라면 잘못 만든 것이다. 접혀 있거나, hover해야 보이거나, 스크롤해야 나타나거나,
링크를 눌러야 도달하는 것은 **존재하지 않는 것과 같다.**

## 1. 캔버스 규격

| 항목 | 값 |
|---|---|
| 폭 | **1000px 고정** (`design_tokens.canvas.width`로만 변경) |
| 높이 | 제한 없음. 통상 6,000~12,000px |
| 배경 | **반드시 불투명.** 투명 배경은 캡처 시 깨진다 |
| 슬라이스 | 폭 1000px · 높이 **최대 2000px** · 섹션 사이 여백에서만 자른다 |
| 파일 | `detail_01.jpg` … 제로패딩 2자리. 순서가 곧 화면 순서다 |
| 용량 | 슬라이스 1장 2MB 이하, 전체 합계 10MB 이하 권장 |

반응형은 **없다.** 미디어쿼리, `vw`/`vh`/`dvh`, `%` 기반 가변 레이아웃을 쓰지 않는다.
1000px은 종이 크기다. 종이는 늘어나지 않는다.

## 2. 모바일 환산 — 이 표가 가독성의 전부다

이 이미지는 모바일에서 **화면 폭에 맞게 자동 축소**된다.
1000px 캔버스가 375px 화면에 들어가면 **약 0.38배**다.

**캔버스 기준 글자 크기 × 0.38 = 소비자가 실제로 보는 크기다.**

| 역할 | 캔버스 기준 최소 | 모바일 실제 | 비고 |
|---|---|---|---|
| 디스플레이(후킹 카피) | **80px** | 30px | 첫 컷의 가장 큰 덩어리 |
| 헤드라인 | **64px** | 24px | 컷마다 하나 |
| 소제목 | **44px** | 17px | |
| 본문 | **32px** | 12px | **이보다 작으면 안 읽힌다** |
| 캡션 | 28px | 11px | 이미지 옆 짧은 설명까지만 |
| 각주·고지 | 24px | 9px | 법정 고지 전용. 본문에 쓰지 않는다 |

웹페이지 감각으로 16px·18px을 쓰면 모바일에서 **6px**이 된다. 아무도 못 읽는다.
"작게 쓰니 세련돼 보인다"는 판단은 이 포맷에서 틀렸다.

## 3. 금지 — 웹페이지의 흔적

전부 **캡처하면 사라지거나 아무 의미가 없는 것들**이다. 하나라도 있으면 build 단계로 되돌린다.

### 3.1 캡처하면 사라진다

| 금지 | 이유 |
|---|---|
| `<details>`/`<summary>` 아코디언, 탭, 캐러셀, 토글 | 접힌 내용은 이미지에 안 나온다. FAQ도 **전부 펼친 상태로 조판**한다 |
| `IntersectionObserver` 스크롤 진입 애니메이션 | 화면 밖 요소가 `opacity:0`인 채로 찍힌다. **가장 흔한 사고다** |
| CSS 전환·애니메이션의 시작 상태(`opacity:0`, `transform`) | 위와 같다. 최종 상태만 존재해야 한다 |
| `loading="lazy"` | 화면 밖 이미지가 로드되지 않은 채 찍힌다. 전부 `eager` |
| `hover`/`focus`/`active` 스타일 | 캡처에 마우스는 없다 |
| `position: fixed` / `sticky` | 슬라이스마다 중복되거나 엉뚱한 위치에 찍힌다 |

### 3.2 이미지에는 존재하지 않는다

| 금지 | 이유 |
|---|---|
| `<a href>` 하이퍼링크, 앵커 이동 | 이미지에는 링크가 없다 |
| 클릭하는 CTA 버튼 | **버튼처럼 보이는 그래픽은 좋다. 링크는 불가.** 누르는 곳은 쇼핑몰의 구매 버튼이다 |
| `<meta name="description">`, OG 태그, `application/ld+json` | 이미지에 아무 영향이 없다. 시간 낭비다 |
| `alt` 텍스트 최적화 | 이미지로 나가면 alt는 존재하지 않는다. 그 노력을 **이미지 안 글자 가독성**에 쓴다 |
| 접근성 헤딩 계층, `<button>` 시맨틱 | 읽는 것은 사람의 눈뿐이다 |

### 3.3 렌더를 망친다

| 금지 | 이유 |
|---|---|
| 외부 CDN(스크립트·CSS·**웹폰트**) | 렌더 시점에 실패하면 **폰트가 통째로 바뀐 채** 찍힌다. 조용히 망가진다 |
| 만료되는 임시 URL 이미지 | 렌더 시점에 404면 빈칸으로 찍힌다 |
| 시스템에 없는 폰트를 이름으로만 지정 | 폴백 폰트로 찍히고 아무도 눈치채지 못한다 |

## 4. 필수

- **모든 텍스트는 HTML로 조판한다.** AI 이미지 모델이 이미지 안에 텍스트를 굽는 것은 여전히 금지다
  (`COMPLIANCE.md` 검수를 통째로 우회하기 때문이다). HTML 조판 후 캡처하는 것은
  검수를 마친 `copy` 문서가 그대로 픽셀이 되는 것이므로 **허용이자 원칙이다.**
- 폰트는 **렌더 머신에 설치된 폰트** 또는 **base64로 HTML에 임베드한 폰트**만 쓴다
- 모든 `<img>`는 `loading="eager"` + 명시적 `width`/`height`
- 법정 고지·각주는 **이미지 안에 실제로 보이게** 넣는다. 접거나 링크로 빼지 않는다
- 렌더 전 폰트 로드 완료(`document.fonts.ready`)와 이미지 로드 완료를 반드시 기다린다

## 5. 후킹 — 이 포맷의 목적

> **누구든 이 이미지를 보면 사고 싶어져야 한다.** 예쁜 것이 아니라 멈추게 하는 것이 목표다.

### 5.1 첫 슬라이스에서 승부가 난다

상단 1000px 안에서 스크롤을 멈추지 못하면 나머지 8000px은 읽히지 않는다.
첫 컷에 반드시 있어야 하는 것:

1. **가장 큰 카피 한 덩어리** — 캔버스 기준 80px 이상, 2줄 이내
2. **무슨 제품인지 알 수 있는 시각 요소** — 제품 컷 또는 사용 장면
3. **왜 남과 다른지** — 한 줄

설명하지 말고 **때린다.** 첫 컷은 요약이 아니라 훅이다.

### 5.2 스크롤에 마디를 만든다

배경색이 바뀌는 구간(**밴드**)을 번갈아 배치한다. 흰색만 8000px 이어지면 눈이 미끄러진다.

```
[진한 밴드 · 후킹]  →  [흰 밴드 · 제품]  →  [연한 밴드 · 문제 공감]
   →  [사진 풀블리드 · 사용 장면]  →  [흰 밴드 · 성분]  →  [연한 밴드 · 사용법]
```

컷 하나는 **한 가지만 말한다.** 한 컷에 두 가지를 넣으면 둘 다 안 읽힌다.

### 5.3 카피는 문장이 아니라 그래픽이다

- 헤드라인은 **읽는 것이 아니라 보는 덩어리**다. 한 줄 12자 이내, 2줄 이내
- 강조는 문장 안에서 **3~7자만.** 색·크기·배경칩·형광펜으로 시각 처리한다
- 한 컷의 본문 총량은 **120자 이내.** 넘으면 컷을 나눈다
- 숫자는 크게 쓴다. `700ppm`, `98.2%`, `300Da`, `150만 개` — 숫자가 가장 강한 그래픽이다

### 5.4 사진이 없는 페이지는 안 팔린다 — 최소 3장

글자만 큰 페이지는 전단지다. **실제 사진이 최소 3장 들어가야 한다.**
페이지가 길어지는 것은 감수한다. 사진을 빼서 짧게 만드는 것보다 길어도 보여주는 편이 낫다.

**필수 사진 3종** — 하나라도 없으면 design 단계가 끝난 것이 아니다.

| 종류 | 무엇을 보여주는가 | 어느 컷에 |
|---|---|---|
| `hero_packshot` | 스튜디오급 제품 단독 컷. 제형·질감·패키지가 또렷하게 | `hero` |
| `model_in_use` | **사람 모델이 제품을 들고 있거나 쓰는 장면.** 크기감과 사용 맥락이 한 번에 전달된다 | `experience` · `how_to_use` |
| `concept_scene` | **컨셉에 부합하는 장소**에서 제품이 부각된 컷. 어디서 쓰는 물건인지 보여준다 | `turning_point` · `core_benefit` |

- 3장은 **최소치**다. 컷이 많으면 더 넣는다
- **"촬영 예정" 플레이스홀더는 사진으로 치지 않는다.** 빈 프레임은 없는 것과 같다
- 3장이 서로 다른 것을 말해야 한다. 같은 앵글 3장은 1장으로 센다

### 5.5 컨셉과 톤앤매너는 처음부터 끝까지 하나다

제품 키워드에서 뽑은 컨셉을 **첫 컷부터 마지막 컷까지 같은 색, 같은 서체, 같은 그래픽 어휘**로
유지한다. 컷마다 스타일이 바뀌면 잘 만든 컷 하나가 아니라 못 만든 페이지 하나가 된다.

`concept.keywords`는 analysis에서 뽑혀 strategy → design → build로 **그대로 전달된다.**
중간에서 바꾸지 않는다. 바꿔야 한다면 strategy로 되돌린다.

## 6. 그래픽 어휘 (컷을 구성하는 부품)

컷은 이 부품들의 조합으로 만든다. 매번 새로운 레이아웃을 발명하지 않는다.

| 부품 | 쓰임 |
|---|---|
| `brand_bar` | 밴드 상단의 얇은 띠. 좌측 브랜드명 / 우측 제품명. 반복되며 페이지를 묶는다 |
| `display_copy` | 초대형 후킹 카피. 밴드 색 위에 얹는다 |
| `highlight_chip` | 단어 뒤 컬러 배경칩 — 문장 속 3~7자 강조 |
| `number_pill` | `01` `02` `03` 원형/알약 넘버 — 나열형 컷 |
| `speech_bubble` | 말풍선 — 고객 목소리, 자문자답 |
| `icon_row` | 아이콘 + 한 줄 설명 반복 — 기능 요약 |
| `cutout_product` | 누끼 제품 컷. 카피 위/옆에 겹쳐 배치 |
| `photo_bleed` | 사진을 캔버스 폭 끝까지 채움 |
| `swatch_grid` | 이미지 격자 + 라벨 — 비교·상태 나열 |
| `step_flow` | 1 → 2 → 3 사용 순서 |
| `spec_table` | 표. 본문 32px 이상 유지 |
| `notice_block` | 고지·각주. 24px 허용되는 유일한 구역 |

## 7. 단계별 책임

| 단계 | 이 문서와 관련한 책임 |
|---|---|
| Analyst | 제품 키워드에서 `concept_keywords`를 뽑는다. 이미지가 **그래픽 소재로 쓸 만한지**(누끼 가능, 카피 얹을 여백) 판정한다 |
| Strategist | 컷 단위로 세로 흐름을 짠다. 첫 컷의 후킹 장치를 명시한다. 컷마다 예상 높이와 밴드를 정한다. **필수 사진 3종이 들어갈 컷을 반드시 확보한다**(§5.4) |
| Designer | 카피를 그래픽 덩어리로 쓴다. 캔버스 기준 타이포 스케일(§2)을 지킨다. 컨셉 컬러·그래픽 어휘를 확정한다. **필수 사진 3종을 실제로 만들어 낸다** |
| Builder | 고정폭 캔버스로 조판하고 **실제로 이미지로 내보낸다.** §3 금지 목록을 하나도 쓰지 않는다 |
| QA | **HTML이 아니라 내보낸 이미지를 눈으로 본다.** 첫 컷 후킹, §2 가독성, 렌더 사고, 슬라이스 경계를 본다 |
