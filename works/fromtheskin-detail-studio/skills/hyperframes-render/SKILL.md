# HyperFrames 합성·렌더

**HyperFrames가 이 페이지의 글자 전부를 만든다.**

## 왜 레이어를 쪼개는가

**문제**: 생성형 AI는 한글 텍스트·로고·숫자를 정확히 그리지 못한다.
그런데 이 페이지 정보량의 대부분이 타이포다 — CHECK POINT 러너, 수치, 각주 3종 세트, FAQ 7문항, AI 고지문.

**해법**: 만드는 주체를 레이어로 쪼갠다.

| 레이어 | 담당 | 내용 |
|---|---|---|
| **L1 · 판(plate)** | Higgsfield | 인물 · 제품 · 배경 · VFX — **픽셀로만 존재하는 것** |
| **L2 · 합성·타이포** | **HyperFrames** | 한글 카피 · 로고 · 수치 · 그래프 · CHECK POINT 러너 · 각주 · 박스 · 구분선 |
| **L3 · 출력** | **HyperFrames** | `snapshot` → PNG (이미지 18) / `render` → MP4 (영상 6) |

### 해결되는 것 / 안 되는 것

| | 대상 | 상태 |
|---|---|---|
| ✅ **완전 해결** | 오버레이 카피 · 로고 · 수치 · 그래프 · 러너 UI · 각주 · 자막 · FAQ · 고지문 | HTML 렌더라 깨질 여지 자체가 없음 |
| ⚠️ **부분 해결** | P07 패키지 정면 컷 (전성분 표기면) | 패키지 디자인 **원본 파일**을 HTML로 정면 합성하면 해결 |
| ❌ **미해결** | **곡면 튜브에 감긴 라벨** · 손에 비스듬히 든 제품의 라벨 (M04·M05·P01) | HyperFrames로 못 고침. `[AI-1]` 대응이 그대로 유효 |

**HyperFrames는 제품 위에 얹는 글자를 해결하지, 제품에 인쇄된 글자를 해결하지 않는다.**

### 부수 효과 (이게 더 큰 이득)

1. **톤앤매너가 구조적으로 보장된다** — 전 블록이 같은 CSS 토큰(컬러·폰트·간격)에서 나온다. 검수 3·4항목이 사람 눈이 아니라 코드로 담보된다.
2. **실증 게이트와 맞물린다** — D1이 늦게 확보돼도 **HTML 변수만 교체하고 재렌더**하면 끝. 디자인 재작업이 없다. 다운그레이드 규칙도 조건부 렌더로 처리 가능.
3. **이미지 블록과 영상 블록이 같은 소스에서 나온다** — B09(이미지 헤더)와 B10(영상)이 동일 컴포지션 계열이라 이질감이 없다.
4. **수정 비용이 선형이 아니다** — 카피 한 줄 고치는 데 이미지 재생성이 아니라 텍스트 한 줄 수정 + 재렌더면 된다. **광고자문 피드백 반영에 결정적.**

## 파이프라인

```
① Higgsfield 판 생성 → assets/ 다운로드      (P0 통과 후에만 다음으로)
        ↓
② hyperframes init                            프로젝트 스캐폴드
        ↓
③ 한글 웹폰트 로컬 임베드                     시스템 폰트 의존 금지
        ↓
④ 디자인 토큰 정의 (컬러·타이포·간격)         전 블록 공유
        ↓
⑤ 재사용 컴포넌트 7종 제작
        ↓
⑥ hyperframes remove-background               제품 누끼 (P01·P02·P05·P08)
        ↓
⑦ 블록별 컴포지션 작성 → lint → preview
        ↓
⑧ hyperframes snapshot → PNG (이미지 18)
   hyperframes render   → MP4 (영상 6)
```

> **컴포지션 작성 착수 시 `hyperframes` 스킬을 진입점으로 로드한다.**
> 컴포지션 계약(`data-*` 타이밍 속성, `class="clip"`, 트랙 구조, 서브 컴포지션)은 그 문서를 따른다.
> 이 스킬은 **파이프라인과 산출물 규격까지만** 규정하고 구현 세부는 위임한다.

## 재사용 컴포넌트 7종

| 컴포넌트 | 용도 | 재사용 |
|---|---|---|
| `CheckPointRunner` | `CHECK POINT │ 01 [02] 03 04 05 │ {영문}` | **5** (CP01~CP05) |
| `StatCard` | 수치 + 라벨 + 3종 세트 각주 | 다수 (D1 해소 시 **값만 주입**) |
| `BeforeAfter` | 동일 규격 2분할 + Before/After 배지 | B10 · B12 |
| `FootnoteBlock` | 각주 (시험기관·시험기간·대상자수) | 전 데이터 블록 |
| `SectionHeader` | 메인 카피 + 서브 카피 조합 | 전 블록 |
| `FaqItem` | Q/A 정적 렌더 | **7** (B22) |
| `SpecTable` | 성분 구성표 | B08 |

`CheckPointRunner` 규격: 좌측 라벨 고정, **활성 번호만 포인트 컬러**, 우측 영문은 대문자 트래킹 넓게.

`StatCard`는 **값을 변수로 받는다.** 하드코딩하면 실증 게이트가 풀릴 때마다 디자인을 다시 짜게 되고,
이 파이프라인을 쓰는 이유의 절반이 사라진다.

## 출력 규격

| 항목 | 값 |
|---|---|
| 캔버스 폭 | **2040px** (@2x) → 슬라이싱 시 1020px로 다운샘플 |
| 이미지 블록 | `snapshot` PNG, 블록 높이별 개별 컴포지션 |
| 영상 블록 | `render` MP4 (H.264), 폭 1020px, 30fps, **오디오 없음** |
| 폰트 | 한글 웹폰트를 **프로젝트에 로컬 임베드** — 렌더 결정성 확보 |

## 분할 예정선에 여백 밴드를 확보한다

퍼블리싱 엔지니어는 논리 블록 1장을 **1,000~1,500px 단위로 세로 분할**한다.
분할 지점이 텍스트·얼굴을 가로지르면 슬라이스 경계에서 글자가 잘리거나 얼굴이 두 동강 난다.

**컴포지션 설계 단계에서 분할 예정선 자리에 여백 밴드를 미리 넣어 두면 슬라이싱이 기계적으로 끝난다.**
그 좌표를 `render_output.split_bands`에 적어 넘긴다. 이건 배려가 아니라 **산출물 규격**이다.

## 부가 커맨드

| 커맨드 | 용도 |
|---|---|
| `hyperframes remove-background` | **제품 누끼** — 배경 분리 후 HTML 레이어로 자유 배치 (P01·P02·P05·P08) |
| `hyperframes lint` | 컴포지션 오류 사전 검출 |
| `hyperframes preview` | 스튜디오 미리보기 (검수 회의용 · 심의 사전 확인용) |
| `hyperframes snapshot` | 렌더 전 레이아웃 검증 겸 최종 PNG 출력 |
| `hyperframes docs` | 인라인 문서 |

## 조판에서 심의가 걸리는 지점

카피가 심의를 통과해도 **조판이 위반을 만들 수 있다.**

- 비포/애프터에 **색보정·노출 보정을 하지 않는다.** 필터 한 겹이 `[S2]` 위반이다.
- 도해에 **흡수 경로 화살표를 그리지 않는다.** 피부 단면은 표피·각질층 스케일을 넘지 않는다. (`[S3]`)
- B06(글루타치온)과 B10(비포/애프터)을 **시각적으로 연결하지 않는다** — 같은 색·같은 파티클로 이으면 조합 위반이다.
- 각주는 **읽히는 크기로** 넣는다. 3종 세트가 있어도 안 보이면 없는 것과 같다.

애매하면 `preview`를 심의 담당관에게 보내 확인받는다.

## 파일이 없으면 완료가 아니다

`lint` 통과와 `snapshot` 파일 생성은 **다른 사건**이다.
`index.html`이 있다고 완성이 아니라 **PNG와 MP4가 실제로 존재해야** 완성이다.
경로를 `render_output`에 적기 전에 파일 존재를 확인한다.
